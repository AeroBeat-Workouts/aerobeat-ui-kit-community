## Overview

This work belongs in the `aerobeat-ui-kit-community` repo, so the plan and Beads stay here. The test scene will live under `.testbed/scenes/` and will be built as a repo-local workbench asset rather than production UI. The goal is to reproduce the feel of the shader demo Derrick shared: a prominent glass element over an image background, plus immediate UI controls for tuning the shader uniforms live.

The implementation will use a `Control`-based scene sized for a 16:9 test viewport, with a background `TextureRect`, a large right/center glass button using a `ShaderMaterial`, and a left-side inspector panel composed of sliders and color controls bound to the shader uniforms. Derrick clarified that the visual target is essentially the full Godot Shaders tester layout: left property controls, large preview area, same general composition, but with AeroBeat’s different background image and without the bottom-right demo buttons shown in the screenshot. The shader source will be captured into the requested `.gdshader` path from the referenced Godot Shaders page, then adapted only as needed to function inside this test scene. Validation will focus on truthful usability: the scene opens in the `.testbed`, the controls visibly change the shader in real time, the composition matches the reference tester closely, and the background asset path is correct.
